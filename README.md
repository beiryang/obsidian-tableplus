# Obsidian TablePlus

为 Obsidian 原生 Markdown 表格提供可持久化的列宽与行高拖拽调整。

TablePlus 不会改写 Markdown 表格内容。所有尺寸记录均保存在插件自己的数据文件中，并在表格增删行列、笔记重命名或 Obsidian 重新打开后自动恢复。

当前版本：`0.1.8`

## 功能特性

- 鼠标靠近单元格右边框或下边框时，显示蓝色拖动线和手柄。
- 拖动竖向手柄调整列宽，拖动横向手柄调整行高。
- 在行列边框交点处，可以同时调整列宽和行高。
- 双击手柄，恢复对应行或列的自动尺寸。
- 按 `Esc` 取消当前拖动，并恢复拖动前的尺寸。
- 每张表格独立保存尺寸，调整一张表格不会影响同一笔记中的其他表格。
- 新增或删除行列后，仍然存在的行列会尽量保持原有尺寸。
- 手动拉宽一列时只改变目标列，不会压缩相邻列。
- 表格超出页面宽度时允许横向滚动，不会在松开鼠标后回弹。
- 满宽表格新增列时，优先压缩已有列；达到最小列宽后保留横向滚动。
- 页面或侧栏临时变窄时只调整显示尺寸，不覆盖已经保存的偏好尺寸。
- 拖动线仅显示在表格和编辑区域的可见范围内，不会延伸到标题栏或工具栏。

## 适用范围

- Obsidian 桌面版。
- Obsidian `1.5.0` 或更高版本。
- 原生 Markdown 表格。
- 实时预览模式和阅读模式。
- 鼠标或支持 Pointer Events 的触控笔。

纯源码模式中的表格仍是 Markdown 文本，不存在可拖动的 HTML 边框，因此不会显示手柄。

## 安装

### 手动安装

1. 从 GitHub Releases 下载最新版本压缩包。
2. 在 Vault 中创建插件目录：

   ```text
   <Vault>/.obsidian/plugins/obsidian-tableplus/
   ```

3. 将以下三个文件复制到该目录：

   ```text
   manifest.json
   main.js
   styles.css
   ```

4. 完全重启 Obsidian，或者重新加载第三方插件。
5. 打开“设置 → 第三方插件”，启用 **TablePlus**。

`data.json` 不属于安装文件。插件首次保存尺寸或设置时会自动生成该文件。

### 从源码构建

需要 Node.js 和 npm：

```bash
npm install
npm run check
```

也可以分别执行：

```bash
npm run test
npm run build
```

构建生成的 `main.js` 位于项目根目录。安装时仍然只需要 `manifest.json`、`main.js` 和 `styles.css`。

## 使用方法

1. 在实时预览或阅读模式中打开包含 Markdown 表格的笔记。
2. 将鼠标移到列边框或行边框附近。
3. 蓝色拖动线和手柄出现后，按住鼠标左键拖动。
4. 松开鼠标保存当前尺寸。

其他操作：

| 操作 | 效果 |
| --- | --- |
| 拖动竖向手柄 | 调整当前列宽 |
| 拖动横向手柄 | 调整当前行高 |
| 拖动边框交点 | 同时调整列宽和行高 |
| 双击手柄 | 恢复当前行或列的自动尺寸 |
| 按 `Esc` | 取消本次拖动并恢复原尺寸 |

## 命令

可以从 Obsidian 命令面板运行：

- `TablePlus: 重置当前笔记的表格尺寸`
- `TablePlus: 重新识别当前页面的表格`

设置页面还提供“重置全部尺寸”按钮。重置操作只删除插件保存的尺寸，不会修改任何 Markdown 文件。

## 设置项

| 设置 | 默认值 | 可调范围 | 说明 |
| --- | ---: | ---: | --- |
| 实时预览模式 | 开启 | 开启／关闭 | 在实时预览表格上启用拖动功能 |
| 阅读模式 | 开启 | 开启／关闭 | 在阅读模式表格上启用拖动功能 |
| 最小列宽 | 48 px | 32–120 px | 自动压缩时允许的最小列宽 |
| 新增列默认宽度 | 120 px | 64–240 px | 新增列采用的初始宽度 |
| 最小行高 | 28 px | 20–72 px | 用户可以调整到的最低行高 |
| 边框感应范围 | 6 px | 3–12 px | 鼠标距离边框多近时显示手柄 |
| 拖动标记颜色 | `#4f9cff` | 任意颜色 | 蓝线和手柄使用的颜色 |

如果单元格内容本身所需高度超过设置的行高，浏览器仍可能撑高该行，以避免裁切文字。

## 尺寸保存机制

TablePlus 将尺寸保存在：

```text
<Vault>/.obsidian/plugins/obsidian-tableplus/data.json
```

插件使用笔记路径、表格位置、列标题和行内容特征识别表格，并将原有尺寸重新关联到当前行列：

- 新增行或列：保留已有尺寸，为新增项分配默认尺寸。
- 删除行或列：移除对应记录，其他尺寸保持不变。
- 修改普通单元格文字：尽量按照原位置保留行高。
- 重命名或移动笔记：跟随 Obsidian 文件事件更新保存路径。
- 多张表格位于同一笔记：每张已渲染表格独占自己的布局记录。

插件采用编辑事件驱动的有限更新方式，不持续监听整个页面的 DOM 或单元格尺寸，避免与 Obsidian 实时预览重绘形成反馈循环。

## 宽度边界规则

手动拖动与新增列使用不同规则：

1. **手动拖动**：只改变目标列。目标列继续拉宽时，表格可以超过页面宽度并出现横向滚动。
2. **新增列**：如果表格已经占满页面，先按可压缩空间缩小原有列。
3. **达到下限**：原有列全部达到最小列宽后，再压缩新增列。
4. **仍然放不下**：保留每列最小宽度，通过横向滚动显示完整表格。

## 已知限制

- Dataview 等插件动态生成的表格可以获得当前页面的拖动效果，但其跨重载尺寸保存取决于生成内容是否稳定。
- 同一笔记中多张内容完全相同的表格如果频繁互换位置，插件可能无法判断它们交换前的身份。
- 不支持在纯源码模式中直接拖动 Markdown 分隔符。
- 移动端触控交互尚未作为主要使用场景进行适配。

## 故障排查

### 表格边框没有出现手柄

- 确认当前处于实时预览或阅读模式，而不是纯源码模式。
- 确认 TablePlus 设置中启用了对应模式。
- 从命令面板执行“重新识别当前页面的表格”。

### 更新版本后仍然表现异常

1. 完全退出 Obsidian。
2. 确认插件目录中三个运行文件均来自同一个版本。
3. 重新启动 Obsidian。
4. 必要时执行“重置当前笔记的表格尺寸”，再重新调整。

提交 Issue 时，建议附上：

- Obsidian 版本和安装器版本。
- 操作系统版本。
- 当前主题名称。
- 实时预览或阅读模式。
- 能够复现问题的最小 Markdown 表格。
- 操作步骤、截图或录屏。
